# Implementation plan: translation (i18n) with a language switch on the profile

Order and shared rules: [`execution.md`](execution.md). Runs after the product reviews agent, on top of every page.

## Goal
- The whole UI is available in **English** (default) and **Brazilian Portuguese**
- The signed-in user picks the language on their profile (`/me`), and the choice is saved on the account, so it follows them to other devices
- Visitors who are not signed in get the language from the browser (`Accept-Language`)
- Product titles (from Amazon) and the reviews people write are never translated. The **AI summary** is generated in the viewer's language

## Spec changes (done by the agent before coding)
- `specs/i18n.md` (new): the requirements below, in the `_template.md` sections
- `specs/home.md`: language switch on `/me`
- `specs/product-reviews.md`: summary in the viewer's language

## How it works (recommended: locale in the URL, as in the Next.js i18n guide)
- **URLs:**
  - every page lives under a locale segment: `/en/home`, `/pt-BR/home`, `/pt-BR/products/<id>`
  - routes move to `src/app/[lang]/…`
  - `<html lang>` is set from the segment (`rootParams`, per `node_modules/next/dist/docs/01-app/02-guides/internationalization.md`)
  - API routes (`/api/**`) don't change, so n8n and the REST API are unaffected
- **`src/proxy.ts`** (Next 16's middleware) redirects URLs without a locale (`/home` → `/pt-BR/home`). The locale is chosen in this order:
  1. the `prs_locale` cookie, set when a signed-in user picks a language and refreshed at sign-in from the account
  2. the browser's `Accept-Language`
  3. `en`

  Old links and bookmarks keep working.
- **Why the URL and not just a cookie:** with Cache Components, reading a cookie in the root layout to choose the language would make every page wait for the request and lose the static shell. A locale segment keeps pages prerendered per language, and shared links open in the right language
- **Dictionaries:**
  - `src/i18n/dictionaries/en.ts` and `pt-BR.ts`, typed so a missing Portuguese key is a **type error**
  - `getDictionary(lang)` on the server
  - a small `I18nProvider` / `useT()` for client components, passing only the messages each page needs
  - no new dependency
  - `t()` from Phase 0 becomes locale-aware; existing calls keep working
- **Formatting:**
  - dates via date-fns with the `ptBR` / `enUS` locales ("Member since October 2026" / "Membro desde outubro de 2026", relative dates)
  - numbers via `Intl` (review counts "1,234" / "1.234")
  - prices stay in BRL ("R$ 1.999,94") in both languages
- **Validation messages:** the zod schemas return message keys; client and server translate them. The REST API keeps English messages, its documented contract
- **Profile switch:**
  - on `/me`, a "Language" control (English / Português) with the language names written in their own language
  - saving updates `accounts.locale`, sets the `prs_locale` cookie and navigates to the same page in the new locale
  - tRPC `account.setLocale` (protected)
  - migration `20261018190000_accounts_locale.sql`: `locale text not null default 'en' check (locale in ('en','pt-BR'))`
  - sign-in returns the account's locale and redirects to `/<locale>/home`
- **Links:** a `localeHref(lang, path)` helper and a `LocalizedLink` wrapper, so no hard-coded `/home` remains (checked by a test)
- **AI summary:** `getOrCreateSummary(productId, lang)` uses the page's locale; the cache is already per locale

## Approved decisions (2026-10-18)
All five approved as written:
1. **Locale in the URL** (`/en/...`, `/pt-BR/...`), with old URLs redirected (recommended). Alternative: keep URLs as they are and use only a cookie. It is simpler, but every page becomes dynamic (no static shell) and links don't carry the language
2. **Languages**: English (default) and Brazilian Portuguese only
3. **Visitors** (landing, sign-in, sign-up) get the browser language; only signed-in users have the profile switch. A small language link in the footer of public pages could be added later
4. **REST API messages stay in English** (documented contract); only the UI is translated
5. **Product titles and user reviews are not translated**; only the AI summary follows the viewer's language
