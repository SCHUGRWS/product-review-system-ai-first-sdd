# Product (Catalog imported from Amazon deals)

## Scope
Automation (n8n), backend, database, frontend (product card)

## Context
Feedback must be about real products. The catalog is filled by a local n8n workflow that reads the Amazon Brazil deals page (https://www.amazon.com.br/deals) and sends the products to the app.

Amazon answers plain HTTP requests with a 503 (bot block) and renders the deal cards with JavaScript. A headless browser gets the page with status 200. n8n therefore calls a local headless Chrome service (Browserless) to render the page and extract the cards.

Deal categories come from Amazon's filter "bubbles" (for example `https://www.amazon.com.br/deals?bubble-id=deals-collection-tvs`). There are 23 categories, such as TVs, video games, books, kitchen and pet products.

## Functional requirements
1. Local n8n environment
    1. `docker compose` file in the repo with n8n (image `docker.n8n.io/n8nio/n8n:2.43.6`, already pulled) and Browserless (headless Chrome)
    2. n8n sends the products to `APP_URL`: `http://host.docker.internal:3000` by default (the app on the same machine), or `https://<project>.vercel.app` for the deployed app, with the same `PRODUCTS_IMPORT_TOKEN` set in Vercel
    3. The workflow is versioned in the repo as JSON and imported with one command. It is imported unpublished, so its schedule is off
2. n8n workflow "Amazon deals import"
    1. Triggers: manual by default (the user clicks "Execute workflow" or runs the CLI command). The workflow keeps an optional Schedule Trigger, once a day at 00:00 (America/Sao_Paulo) while n8n is running, which ships off: it fires only after the user publishes the workflow (`pnpm n8n:schedule:on`, documented in `n8n/README.md`)
    2. For the general deals page and for each category: render the page in Browserless, scroll to load more cards, extract the cards
    3. Fields per card:
        1. ASIN (`data-asin`)
        2. title
        3. product URL
        4. image URL
        5. deal price, list price ("De:") and discount %
        6. rating and review count, when shown
        7. category
    4. One category at a time with a pause between them (low load on Amazon, smaller chance of being blocked)
    5. Sends the products to the app in batches (at most 100 per request)
    6. One category failing does not stop the others; the run ends with a summary (categories, products sent, failures)
3. Import endpoint `POST /api/v1/products/import`
    1. Authenticated by `Authorization: Bearer <PRODUCTS_IMPORT_TOKEN>` (server env var, compared in constant time). It is not a user session
    2. Body: `{ category: { slug, name }, products: [...] }`
    3. Validates and normalizes each product:
        1. prices like "R$ 1.999,94" become integer cents
        2. the URL becomes the canonical `https://www.amazon.com.br/dp/<ASIN>`, without tracking parameters
        3. only `m.media-amazon.com` images are accepted
    4. Invalid items are skipped and reported. The rest of the batch is saved
    5. Upserts by ASIN: price, discount, rating, image and `last_seen_at` are refreshed
    6. HTTP codes
        1. 200: `{ received, saved, skipped: [{ index, reason }] }`
        2. 400: bad body (not JSON, no category, more than 100 products)
        3. 401: missing or wrong token
        4. 500: unexpected server error
4. New database table 'products'
    1. id: nanoid-style, generated by the database (kept when a product is imported again, so feedback links stay valid)
    2. asin: text (Unique)
    3. title: text
    4. url: text
    5. image_url: text
    6. price_cents: integer
    7. list_price_cents: integer (nullable)
    8. discount_percent: smallint (nullable)
    9. currency: text ('BRL')
    10. rating: numeric(2,1) (nullable)
    11. review_count: integer (nullable)
    12. category_slug: text
    13. category_name: text
    14. first_seen_at: timestamp
    15. last_seen_at: timestamp
    16. search: tsvector generated from the title (Portuguese), with a GIN index
5. A product is "available" when it was seen in the latest import: its `last_seen_at` falls within 3 days before the most recent `last_seen_at` in the table (`last_seen_at > max(last_seen_at) - 3 days`, computed in SQL). With manual imports the catalog does not empty itself days after the last run. Lists, category pages, search and category counts show only available products; an empty table gives empty lists. Product pages and feedback keep working for older products
6. Reading products (server, for home and feedback)
    1. list categories that have available products
    2. list available products by category; sorted by discount, by rating, or by most recently seen
    3. full-text search over titles, at least 2 characters, paginated; results ordered by Amazon review count, then rating
    4. get one product by id
    5. tRPC procedures `product.search` and `product.byId` (signed-in users)
    6. Lists, category grids and search add the app's review count and average to every product of the page with one extra query for the whole page (SQL function `product_review_stats(ids)`), never one query per product. If that query fails, the products are still listed without the app's numbers
7. Product card component (used by home)
    1. Shows image, title, price, list price crossed out and discount badge
    2. The app's own reviews come first: stars, the average to one decimal and the count ("4.3 · 3 reviews here"), or "No reviews yet"
    3. Amazon's rating is secondary (smaller, slate) and labelled as Amazon's: "4.6 on Amazon (1,234 reviews)", or "4.6 on Amazon" without a count; hidden when Amazon shows no rating
    4. The title is a link to the product page on Amazon (new tab, `rel="noopener noreferrer nofollow"`)
    5. "Give feedback" button opens the feedback page for that product (`specs/feedback.md`)
    6. A link (secondary style) next to it opens the product reviews page '/products/<id>' (`specs/product-reviews.md`): "See 3 reviews" when the product has reviews in the app, "See feedback" otherwise

## Non-Functional requirements
- Reliability
    - The scraper breaks if Amazon changes its HTML. Selectors live in one place in the workflow, and the endpoint rejects incomplete items instead of saving broken products
- Performance
    - Images through `next/image` with `unoptimized`: the browser loads them straight from `m.media-amazon.com`, never through Vercel Image Optimization (Hobby quota). Amazon's own size tokens give the 1x / 1.5x / 2x `srcSet` (`_AC_SF226,226_QL85_`, `_AC_SF339,339_QL80_`, `_AC_SF452,452_QL80_`); fixed width and height (no layout shift), lazy loaded, `referrerPolicy="no-referrer"`
    - Indexes for category lists and search
- Security
    - The import token is only in server env vars and in the n8n credential, never in the repo
    - Only `m.media-amazon.com` images and `www.amazon.com.br` links are rendered

## Must do
- Docker Compose for n8n + Browserless, the workflow JSON, and the import instructions
- Products migration, import endpoint, product queries and tRPC procedures
- Product card component
- Test and validations

## Must not do
- Buy anything, add to cart, or log in to Amazon
- Use Amazon's paid APIs (PA-API / Creators API)
- Build the home page lists or search UI (`specs/home.md`)
- Store Amazon's customer reviews (only their rating and count)
- Run the import automatically by default, or more often than once a day when the schedule is on
- Send product images through Vercel Image Optimization

## Technologies (Stack)
- n8n (local, Docker)
- Browserless (headless Chrome, Docker)
- Next.js, tRPC, Zod
- Supabase (PostgreSQL full-text search)

## Acceptance criteria
- `docker compose up` starts n8n and Browserless; the workflow is imported with one documented command and is not active afterwards (no scheduled run until the user turns it on)
- Running the workflow manually fills `products` with real deals from at least 5 categories
- Running it again updates prices and `last_seen_at` without duplicating products
- With the latest import 30 days ago, its products are still listed; products seen 4+ days before the latest import are hidden
- Product images are rendered `unoptimized`, straight from `m.media-amazon.com`
- The import endpoint rejects requests without the right token (401)
- The product card links the title to Amazon and has working "Give feedback" and "See feedback" / "See N reviews" buttons
- A product with reviews in the app shows "N reviews here" and their average on its card; Amazon's rating reads "… on Amazon"

## Results
The app has a catalog of real, current products that users can browse and review.
